<h2>What changed</h2><p>Amazon GuardDuty Runtime Monitoring is now included in the AWS Security Hub Threat Analytics plan. Previously a separate service add-on, Runtime Monitoring now comes bundled with Security Hub's threat detection offering. This means a single plan now covers both cloud-level threat intelligence and workload-level runtime inspection across EC2 instances, EKS clusters, and ECS tasks running on Fargate.</p><h2>What it monitors</h2><p>Runtime Monitoring inspects operating system behavior, network activity, and file system operations to detect threats that occur while workloads are running. The service specifically looks for container escapes, privilege escalation attempts, and cryptomining activity—threats that traditional perimeter defenses miss because they happen inside already-running compute environments.</p><h2>Why it matters</h2><p>This bundling simplifies procurement and reduces billing complexity for teams already using Security Hub. Instead of managing separate line items for cloud threat detection and runtime monitoring, organizations get both under one plan. For shops not yet running runtime monitoring, this removes a procurement hurdle—you're already paying for the capability if you're on the Threat Analytics tier.</p><h2>What to do</h2><p>If you're currently subscribed to Security Hub's Threat Analytics plan, verify that Runtime Monitoring is now active for your EC2, EKS, and Fargate workloads. If you've been paying for GuardDuty Runtime Monitoring separately, check whether this consolidation changes your monthly bill. For teams evaluating runtime security options, this bundling makes Security Hub a more complete offering without requiring a separate vendor or AWS service activation.</p>
