<h2>What changed</h2><p>GitHub has made issue types and custom fields generally available for repositories owned by personal accounts. Previously, these structured planning capabilities were only accessible to organization accounts, creating a feature gap for solo developers and open source maintainers working outside formal organizations.</p><h2>Why it matters</h2><p>This levels the playing field for individual maintainers managing complex projects. Issue types let you distinguish between bugs, features, and documentation tasks without relying on label conventions. Custom fields add structure to issue tracking—think priority levels, effort estimates, or release targets—making it easier to organize work without jumping to full project management tools.</p><h2>What to know</h2><p>The feature parity means personal account repositories can now standardize issue workflows the same way enterprise teams do. For open source projects, this could reduce friction in contribution workflows by providing clearer issue categorization. If you've been using labels and milestones as workarounds for structured metadata, you now have native tooling to replace those patterns.</p>
